# 案例契約與驗收資料

撰寫或調整案例文字 manifest 時讀本檔。下列六個欄位相容於原 `ManualVerificationBuilder.CaseInfo`；新增欄位若要供程式使用，先同步其 DTO 與讀取端。

```json
[
  {
    "id": "H01",
    "title": "自動吊架",
    "tool": "autoHanger",
    "steps": [
      "在本案 A 試作區選來源管，開啟名稱為自動吊架的工具。",
      "採本案已確認的中文吊架族群／類型，關閉保溫；間距 2000、首末端距離各 150 mm，以樓板結構錨定。",
      "預覽核對四站後套用，以來源起點為 local X=0 讀回位置與尺寸。",
      "與 B 完成對照比較，再執行一次 Revit 原生 Undo，確認回到操作前。"
    ],
    "expected": [
      "四站 local X=150、2050、3950、5850 mm；來源長 6000 mm。",
      "本案例已確認來源外徑 60.3、中心標高 1000、結構底 2700 mm；結果對應尺寸／錨定與契約相符。",
      "來源、結構及 B 區參考保留，Undo 僅復原本次操作。"
    ],
    "scopeNote": "只選本案 A 區；局部 X 不能當成全模型 X。B 區無插件實例所有權且已釘選。"
  }
]
```

這是初版單吊架案例的具體範例，不代表每個插件或當前模型都應使用相同數值。執行前以族群目錄補足確切族群／類型，不能把「本案已確認」當成已完成查證。

## 建模與檢查分開定義

在專案現有測試機制保存數值期望與容差；文字 manifest 不是唯一的數值 oracle。可用參數公式、布置規則與來源幾何獨立算出：

- 自動站點：6000 mm 管長、端距 150、間距 2000，契約站點為 150／2050／3950／5850；來源起點及方向先固定。
- 位移：比較操作前後同一 ID／UID 的世界座標差，再投影到來源方向；不能只讀移動距離輸入框。
- 更新：來源變更是初始前置；Undo 應回到舊成品配新來源的起始狀態，不應把來源前置一起還原。
- 方向：比較實體橫擔或夾具孔軸與來源／支承方向，並處理族群自身局部軸；單看 Rotation 不足。
- 連結：`主模型點 = 連結實例轉換 × 來源點`，參考區位置不是複製目標。
- 統計：由受管選取集合、組套政策、原生參數與單位獨立加總，區分實例數、組數和材料長度；不要把參考成品計入。

舊 LKBIMHanger 教材的人工尺寸／位置容差為 1 mm、角度 0.1°，數量精確一致。新插件依功能選容差；程式或原生 API 的精度需求可比人工更嚴格。

## 每案最少要有的證據

| 時點 | 要記錄的內容 |
|---|---|
| 起始 | 文件路徑與身分、宿主／插件版本、來源與受驗 ID／UID、位置／類型／管理狀態、設定基線 |
| 預覽 | 實際選取與範圍、輸入值、預覽筆數、拒絕或略過原因 |
| 套用 | 交易提交狀態、提交／失敗／未執行數量、原生尺寸與幾何、參考區與來源是否保留 |
| 恢復 | 一次原生 Undo 後與起始狀態比較；設定類改記重新載入後的值，模型 Undo 填不適用 |

用 Core 產生參考模型、TransactionGroup 回滾、重核舊 JSON、查看 Mock UI，各自只支援其實際範圍，不能填入正式 UI／Undo 或使用者人工通過欄。

## 特殊案例的教材設計

- 設定：另存唯一名稱的測試設定，不覆寫使用者檔；關窗重開、選載、讀回，再恢復原設定。若會影響後續案例，將恢復放入必要步驟。
- 全文件刪除：圖紙明示影響所有案例的受管集合；不是當前裁切框範圍。不得為了跑測試自行在現用主檔執行未授權的大量刪除；優先用已授權測試環境，不能執行時保留待人工驗證。
- 多次套用：不同管夾類型、兩種統計等，每次各自保存基線、套用與 Undo，避免一次 Undo 驗不到所有結果。
- 重用教材：維護使用者實際保留的位移、附加管線／管夾和設定。若現況與初始契約不同，標明本次可驗範圍及歷史預期，不改數值湊 PASS。
